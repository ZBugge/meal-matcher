# Full local verification

Run `npm run verify` from the repository root after dependencies and Playwright Chromium are installed. It runs the entire verification workflow in one invocation, with a 120-second elapsed-time budget:

- All server and client unit/component tests, including real HTTP requests through the application routers, database persistence/reopening, and rejected-ballot preservation. No test filters, cached results, or focused tests.
- Client lint and both complete production builds (client TypeScript plus Vite; server TypeScript).
- All browser scenarios, including independent participant contexts, phone-sized recipe/library access, partial swipe reload/back recovery, submitted-choice editing, explicit retry after a failed submission, family week planning/shopping/cooking across independent same-account logins, and both library and quick-session voting results added to the plan.
- A compiled Worker/Static Assets/D1 smoke check, after both builds and Worker packaging pass: SPA routes/assets, anonymous voting/results, privacy, cookie security from the actual HTTPS request URL, durable login/votes after Worker restart, installation assets and a browser service-worker update/offline check that caches no private APIs. Local HTTPS request simulation does not certify hosted TLS.
- Six deliberate mutations in isolated source copies. The tests must catch invalid votes, rejected-ballot loss, public voter disclosure, anonymous-close disclosure, recipe ownership bypass, and lost disk persistence. An unmodified control must pass first; intended assertion mismatches must fail each mutant. Missing anchors, surviving mutants, setup errors, skipped tests, and crashes fail the audit.
- Regression checks for verification failure reporting, dependent-gate ordering, report integrity, mutation-error classification, and process-tree cleanup.

Independent gates run in parallel with bounded workers: two each for tool files, client tests and recovery files, and three server/browser workers. A fresh closed Wrangler-migrated seed is prepared alongside the builds and copied with source/schema/content verification into independent server, browser, production-smoke and mutation-probe databases. Mutation copies must additionally retain the original verified schema and binding configuration; no migration-ledger rows or template attestations are fabricated. Standalone checks still migrate their own databases. No assertions, test timeouts or full deadline are changed; host CPU/memory diagnostics help diagnose timing. Every invocation starts fresh local Workers on allocated ports with isolated D1 state; it never reuses a preview. Browser assets and API share one origin. No Vite proxy or filesystem SQLite application server participates in authoritative tests.

Server unit tests also receive a fresh temporary database before each test file imports database code, including when running ordinary `npm test`. This corrects the legacy matching tests' assumption that the default database was in memory. Unit tests never use the developer's default database or an inherited `DATABASE_PATH`; their own temporary directories are removed after each file.

Success requires every gate to pass, no skipped/flaky or expected-failure tests, at least 201 server/153 client/38 browser tests, and total elapsed time below 120 seconds. Every historical server test must also be individually accounted for by file/name in `cloudflare-test-baseline.json`; a higher count cannot hide a dropped assertion. Deliberate renames require one-to-one mappings with reasons in `cloudflare-test-mappings.json`. A failed gate does not hide independent results; dependent gates wait for prerequisites. A deadline, interruption, cleanup error, missing report/browser/assertion or reduced coverage fails verification.

Worker packaging validates that frontend assets were built from the current client inputs. The receipt binds source/config/migrations, assets and Worker bytes; the final verification report binds those exact hashes. A stale/tampered source, asset or Worker cannot be accepted as verified. Compatibility and migration recovery tests use real local D1 and Wrangler's migration ledger. Restore tests and fixtures never select existing family or Notion databases.

Logs, timings, browser reports, and phone screenshots are written to ignored `.verification/run-*/` directories. `.verification/latest.json` points to the latest invocation's `summary.json`; inspect that summary's `passed`/`status` fields, not an older browser report. Only the pointer is published under the checkout lock, so an earlier run cannot overwrite a newer run's status. The default Playwright output and tracked `test-results/.last-run.json` are not touched by this command. The command does not install packages or launch a persistent preview.

Dependencies are a one-time setup using `npm run install:all`, plus `npx playwright install chromium` if needed. That installation time is outside the repeated verification budget. In Codex on this Windows machine, run the command with approved access outside the sandbox: the sandbox prevents Vite file resolution and local browser/network access. One invocation replaces repeated per-check tool calls and permissions retries.

The machine's `F:/Git` 2.49 executable was observed crashing with Windows access violation 3221225477 on isolated fixture `git add`. The bundled Codex runtime Git passed the same fixture. If this recurs, prepend a working Git installation to PATH for the verifier; do not disable Git ownership/receipt tests or change global user configuration. Fixture repositories use an empty template to avoid machine-wide sample-hook dependencies.

If another verification is already running in this checkout, wait for it to finish. Its lock prevents collisions between the existing unit-test database fixtures. A terminated/crashed runner can leave `.verification/verify.lock`; confirm the PID in that file is no longer running before removing that specific lock file. Reports/database artifacts can be retained for diagnosis; never delete or replace the developer's persistent database to speed up testing.

This preserves the existing local Chromium baseline. It does not certify real iPhone/Safari behavior or deployment; inspect the generated phone screenshots when UI changes and test device-specific behavior on the target phone when relevant. Real Worker/D1 server cases and the multi-step takeout component case have a bounded 10-second allowance; the legacy five-second Vitest default was not an application latency contract. The process cleanup assertion allows up to one second for asynchronous OS kill delivery, still rejects live processes, and does not rerun any test. All assertions, zero retries and the full 120-second budget remain unchanged. The timing budget applies to the complete verification command on the measured machine, rather than promising constant duration on every machine or including new feature design/debugging time.

For a focused repeat of the adversarial API/persistence checks, run `npm run audit:adversarial`. It creates fresh ignored source copies and temporary test databases; it never mutates application source in this checkout. The complete `verify` command includes this audit automatically.

For each feature, identify its likely failure first, add an assertion that would detect it, and verify that assertion against the broken behavior when practical. Review storage, ownership, and client/server changes independently. Extend the targeted mutation set when a consequential regression exposes weak coverage. These six mutations are repeatable evidence for selected failure modes, not a claim that every possible bug is covered.
